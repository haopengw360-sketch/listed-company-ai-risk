# 项目调参与训练说明

## 一 数据划分

模型不用随机拆分。每一行以第 t 年指标预测第 t+1 年是否亏损，按时间分成：

- 滚动验证一：2020 年训练，2021 年验证；
- 滚动验证二：2020—2021 年训练，2022 年验证；
- 阈值选择：2020—2021 年训练，2022 年选择使 F1 最高的分类阈值；
- 最终训练：2020—2022 年训练；
- 锁定测试：2023 年指标预测 2024 年亏损，测试集不参与参数或阈值选择。

这样可以模拟银行实际使用场景：只用当时已经获得的信息预测未来。

## 二 数据预处理

1. 以证券代码和年度连接财务与年报文本；
2. 将无穷值转换为缺失值，连续变量用训练集的中位数填补；
3. 逻辑回归对特征做标准化，XGBoost不要求标准化；
4. 亏损样本比例较低，使用 `scale_pos_weight=负样本数/正样本数` 调整类别权重；
5. 下一年度净利润只用于生成标签，不能进入特征。

## 三 XGBoost 调参

脚本使用固定随机种子的参数抽样，共搜索36组组合。参数空间包括：

| 参数 | 搜索范围 | 作用 |
|---|---|---|
| `n_estimators` | 250、400、550、700 | 树的数量 |
| `max_depth` | 2、3、4 | 控制单棵树复杂度 |
| `learning_rate` | 0.02、0.04、0.07 | 每棵树的更新步长 |
| `min_child_weight` | 3、6、10 | 限制过小叶节点 |
| `subsample` | 0.75、0.90 | 每棵树使用的样本比例 |
| `colsample_bytree` | 0.75、0.90 | 每棵树使用的特征比例 |
| `reg_alpha` | 0、0.1、0.5 | L1正则化 |
| `reg_lambda` | 1.5、3、6 | L2正则化 |

每组参数分别在2021年和2022年两个验证折上计算ROC-AUC和PR-AUC，先按平均ROC-AUC、再按平均PR-AUC排序。选择参数后重新训练，并只在最后读取一次2023→2024测试集结果。

运行命令：

```bash
python src/tune_xgboost_temporal.py --source-dir ../source_materials --config configs/experiment.json
```

## 四 分类阈值

XGBoost默认0.5阈值不一定适合经营风险预警。项目只在2022年验证集上搜索0.10—0.90的阈值，以F1最高为准。阈值降低通常会提高召回率，但会增加误报；阈值提高则相反。银行预警场景更关注识别潜在风险企业，因此同时报告召回率和PR-AUC。

## 五 Transformer训练

1. 从年报中筛选含风险、亏损、减值、诉讼、现金流等词的高风险句；
2. 使用 `BAAI/bge-small-zh-v1.5` 将每份年报编码为512维语义向量；
3. 只在训练数据上拟合PCA，搜索16、32、64个主成分；
4. 搜索逻辑回归正则化参数C为0.05、0.2、1.0；
5. 在2022年验证集搜索BGE模型与财务文本模型的融合权重；
6. 用固定的参数和权重评估2023→2024测试集。

当前Transformer融合提高了选定阈值下的F1和准确率，但ROC-AUC低于词典融合XGBoost，因此保留为模型比较，不作为“全面优于基线”的结论。

## 六 方法摘要

项目不随机拆分样本，而是采用滚动时间验证：先用2020年预测2021年，再用2020—2021年预测2022年，按两个验证折的平均AUC选择XGBoost参数；随后只在2022年选择分类阈值，最终用2020—2022年训练并锁定测试2023→2024。该设计可以避免未来信息泄漏，并模拟真实的年度风险预警流程。

年份、候选参数数量、随机种子和模型晋级门槛均由 `configs/experiment.json` 管理。新增年度数据时只需更新配置并重新运行调参脚本，实验配置指纹、数据指纹与测试指标会写入实验登记表。
